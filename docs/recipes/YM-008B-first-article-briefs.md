# YM-008B First Article Briefs

[YM-008A](YM-008A-recipe-seo-foundation.md) の P0 backlog に対する着手用 Brief。作成日 2026-09-02。

## この文書の位置づけ

**ここに書かれたレシピはどれも検証済みではない。**

材料・分量・手順・加熱時間は、Human が実際に作って確認するまで確定しない。
各 Brief の「Human が確認すること」は、AI が確認できないので人間に回す項目であり、
省略できる確認項目ではない。

Brief の段階では `data/recipes.ts` に何も書き込まない。Gate 2（調理検証）を通ってから
`status: 'draft'` で起こし、Gate 3（独立レビュー）と Gate 4（公開承認）を経て `published` にする。
これは人が守る運用規則であり、コード上の既定値ではない（YM-008A 11章）。

各 Brief の「候補材料」は、このリポジトリの canonical data に限る。出典は Brief ごとに明記した。

- **既存レシピ**: `data/recipes.ts` の Human 確定内容。
- **商品データ**: `data/catalog.ts`。

この2つで確認できない材料・分量・時間・保存条件・商品事実は、Brief に書かない。
旧サイトや Internet Archive の本文は canonical data ではないため、出典として使わない。
canonical data に無い調理条件は、Gate 2 で Human が実測して初めて確定する。

## 全 Brief 共通の Human Gate

Gate 2（調理検証）で確定するもの:

| 項目                 | 確定しないと                                    |
| -------------------- | ----------------------------------------------- |
| 材料と分量           | 読者が作れない                                  |
| 手順と加熱時間       | 失敗する。焦げる                                |
| `servings`           | 未確定なら**設定しない**（YM-007 の判断を維持） |
| `cookingTimeMinutes` | 未確定なら**設定しない**                        |
| 味の評価・おすすめ   | 食べていない評価は書けない                      |
| 食品安全の記述       | 健康被害になりうる                              |
| 写真                 | `Recipe` 構造化データが出ない                   |

Gate 2 を通っていない Brief は、運用規則として `status: 'draft'` にとどめる。`draft` は
ルート・一覧・サイトマップのいずれにも出ない（`lib/recipe-page.ts`）ので、この規則を守るかぎり
未検証レシピが公開される経路は無い。`status` に既定値は無く、レコードごとに明示的に書く。

## 公開順の推奨

1. Brief 1（写真）— 既存資産が先に立ち上がる
2. Brief 2 → 3 → 4 → 5（Cluster B）— 独自性が高く、撮影も1品ずつ完結する
3. Brief 6 → 7（Cluster A）— 確認事項が多く、食品安全に触れるので時間を取る

Cluster B を先にするのは、商品ページとの往復リンクが1本ずつ増えて
`/products` 側も同時に厚くなるためで、検索数の推定によるものではない。
