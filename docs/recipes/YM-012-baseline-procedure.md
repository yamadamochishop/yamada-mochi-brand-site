# YM-012 公開前の基準値取得手順（Human）

対象URLは `/recipes/mochi-yakikata` と `/recipes/isobeyaki`。公開前に取得日・タイムゾーンを記録し、同じ定義で公開後に再取得する。リポジトリには集計値だけを置き、個人情報や生のユーザー単位データは入れない。

## Search Console

1. 検索パフォーマンスで検索タイプ「ウェブ」を選ぶ。期間を直近28日、直近3か月、前年同時期（取得可能なら）に切り替える。前年分が取得できない場合は欠測と記録する。
2. ページのフィルタで対象URLを1件ずつ完全一致指定する。ページ別の表示回数、クリック、CTR、平均掲載順位を記録する。
3. 各ページの「検索キーワード」表をエクスポートし、検索語別にも同じ4指標を記録する。匿名化・集計制限で表示されない検索語は推測しない。
4. エクスポートはCSVまたはスプレッドシートを用い、Human管理の保存先に `YM-012_GSC_<slug>_<period>_<取得日>` と命名する。リポジトリに置く場合は集計表だけにする。

## GA4

1. 探索レポートで同じ3期間と2つのランディングページを指定し、チャネルグループ `Organic Search` に絞ったランディングのセッションとエンゲージメントを取得する。これは既存SEO流入の表とする。
2. 別の表で2ページ間・他ページからのページ遷移を確認し、`recipe_view`、`recipe_to_product_click`、`base_click`、`sales_channel_click` の件数を取得する。これはサイト内回遊・導線の表とする。外部ECクリックを購入数と呼ばない。
3. ディメンション、フィルタ、期間、取得日を集計表に併記する。イベントパラメータのカスタムディメンション登録状況もHumanが確認する。
4. エクスポートはHuman管理の保存先に `YM-012_GA4_<seo-landing|site-navigation>_<period>_<取得日>` と命名する。リポジトリに置く場合は集計値だけにする。
