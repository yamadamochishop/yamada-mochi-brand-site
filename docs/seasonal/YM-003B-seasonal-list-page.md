# YM-003B Seasonal List Page

## Scope

- Publishes `/seasonal` as an indexable list page.
- Reads the ten YM-003A `SeasonalProductRecord` entries through a list-only view model.
- Keeps every seasonal record `draft`; no `/seasonal/[slug]` route, detail metadata, static params, or sitemap entry is created.
- Adds `/seasonal` to the shared header, footer, current URL registry, and sitemap.

## Deterministic current view

`SEASONAL_LISTING_MONTH = 8` is a human-managed display setting. It highlights August and builds the confirmed four-item current panel. It never changes `availabilityStatus` from the calendar or from build time.

`check:content-model` emits a non-blocking warning when this setting differs from the current month in Asia/Tokyo.

## Month anchors

Each month chip links to a unique monthly summary generated by the YM-003A calendar logic. The summary is derived from `salesPeriod`, including cross-year periods. A separate product directory shows complete metadata once per product, so the month controls remain accurate without repeating full cards.

## Publication and CTA safety

- List visibility and detail publication are separate concerns. The list view explicitly selects YM-003A records while their publication status remains `draft`.
- Product and Offer JSON-LD are intentionally omitted because price and offer conditions are not confirmed.
- Commerce status is rendered as text only. The list page renders no seasonal commerce links, even where confirmed channel names exist without URLs.
- Instagram displays the confirmed account name only. A link is deferred until the official URL is registered in site data.

## Image policy

When `images` is empty, no image element or placeholder container is rendered. A future real asset may use the optional image branch without changing the text-first layout.
