# Claude Code・Codex 運用ルール（山田もち店ブランドサイト）

このプロジェクトはChatGPT・Claude Code・Codexが協働して開発します。役割と作業ルールを明確にし、事故（誤デプロイ・意図しない変更・認証情報漏洩）を防ぐことを目的とします。

## 全体フロー

```
ChatGPT
  ↓  要件定義・設計・優先順位決定
Claude Code
  ↓  作業管理・実装依頼・Build確認・Review・Git管理・Deploy
Codex
  ↓  実装・テスト・修正
Claudeレビュー
  ↓  差分確認・Build確認・副作用確認
ChatGPT最終確認
```

## 役割分担

### ChatGPT

- 要件定義（何を・なぜ実現したいか）
- 設計方針の検討
- 複数タスクがある場合の優先順位決定

### Claude Code

- 作業内容をタスクに分解し、進行管理する
- 実装が必要な作業をCodexに依頼する（依頼プロンプトの作成）
- Codexの成果物をレビューする（差分・Build・副作用）
- `pnpm run check`（lint / typecheck / build）の実行
- Gitの管理（ブランチ作成・コミット・push・PR作成）
- 本番デプロイの実行と反映確認
- Codexが実装できない・止まった場合の作業引き継ぎ

### Codex

- 指定されたファイル・範囲内での実装
- テスト・動作確認（可能な範囲で）
- Claude Codeからの修正依頼への対応

## 作業ルール

### 1. 実装前は必ずブランチ作成

- 複数ファイルにまたがる変更・新機能・依存関係の変更は、作業ブランチを作成してから着手する（詳細は [GIT_WORKFLOW.md](./GIT_WORKFLOW.md)）。
- 影響範囲が1ファイル・軽微な修正に限り、Build確認済みであれば`main`直pushを許容する。

### 2. Build成功後のみDeploy

- `pnpm run lint` / `pnpm run typecheck` / `pnpm run build` がすべて成功したことを確認してからpush・デプロイする。
- pushしたら、Vercelダッシュボードで対象コミットのデプロイが `Ready` になったことを確認する。

### 3. 大規模変更は事前確認

- 複数ページ・複数コンポーネントにまたがる変更、依存関係の大幅な更新、デザインシステムの変更などは、着手前にユーザーへ計画を提示し、承認を得てから実行する。
- 「新機能追加」「UI変更」「商品情報・SEO内容の変更」を伴うタスクでは、対象範囲を明示的に確認する。

### 4. APIキー・認証情報は表示・保存しない

- `.env` / `.env.local` などの環境変数ファイルの中身、APIキー、トークン、認証情報を出力・ログ・コミットに含めない。
- 認証系のファイル（`auth.json` 等）の内容を画面に表示しない。誤って表示してしまった場合は速やかに報告する。
- 環境変数の値を確認する必要がある場合は「設定されているかどうか」のみを確認し、値そのものは扱わない。

### 5. Codexへの依頼ルール

- **非対話実行（`codex exec`）は最大実行時間10分を目安とする。**
- 10分以内に完了しない場合:
  1. バックグラウンドタスクを停止する
  2. `git status` / `git diff` で変更有無を確認する
  3. 残存プロセスがないか確認する
  4. 承認待ち・入力待ち・エラーが発生していないか確認する
  5. 変更が行われていなければ、同じ依頼を再実行せず、Claude Codeが作業を引き継ぐ
- Codexのサンドボックス（`workspace-write`）はネットワークアクセスがブロックされるため、新規パッケージのインストール（`pnpm add`等）はCodexの変更内容をレビューした後、Claude Code側で実行する。
- 依頼プロンプトには「対象ファイル」「変更してはいけない範囲」「完了条件（build成功など）」を必ず明記する。

### 6. レビュー観点（Claude Code）

Codexの成果物をレビューする際は、最低限以下を確認する。

- 差分が依頼内容の範囲に収まっているか（無関係なファイルへの変更がないか）
- `pnpm run lint` / `typecheck` / `build` が成功するか
- UI・文章・SEO内容・商品情報など、変更対象外の情報が変わっていないか
- 認証情報・APIキーが含まれていないか
