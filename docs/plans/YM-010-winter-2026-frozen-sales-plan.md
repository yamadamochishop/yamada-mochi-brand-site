## 0. 結論（先に読む）

1. **冷凍便の商品化と公式HPへの掲載は完了済み**（PR #27、2026-10-05 merge）。冷凍便4商品・常温便4商品のBASE個別URL、価格、包装、別便送料の案内、冷凍保存の目安、焼き方は公式HPとBASEの両方に出ている。**重複開発を避けるため、商品データとセットの導線そのものは作り直さない。**
2. 残っている課題は「冬に売れる形に並べ替える」ことと「食品表示と安全性の根拠を固める」こと。
   - スマホで、冷凍便に行き着くまでが遠い。公式HP `/products` では、セット商品は約5,100px下（約6.3画面分）にある。BASEトップでは冷凍便4商品は約8,700px下（約11画面分）で、一番下に並ぶ。
   - 年末に必要な情報がHPにもBASEにもない。年内お届けの締切、年末年始の発送予定、冷凍便の送料目安。
   - 計測ができていない。GA4の `base_click` は `placement` しか送らないため、冷凍便と常温便、6袋と12袋のどれが選ばれたか分からない。
   - 食品表示に未確認事項が4件ある（§3.3）。とくに冷凍便商品の賞味期限表示が、BASEでは「商品表示をご確認ください」のままになっている。
3. 優先順位: **P0＝Humanの食品安全・スケジュール判断 ＋ 判断不要な導線改善（WP-1, WP-2）** → P1＝年末スケジュール表示・送料目安・SEO（WP-3〜5、Human確定後） → P2＝表示整合・新米・実績掲載。
4. 利益面で注意すること（§4.4）。ご自宅用なら、常温の単品をネコポスでまとめ買いするほうが、常温6袋セットより1袋あたり安い（535円と587円）。冷凍便はセットでしか買えず、6袋ご自宅用では関東までの送料が合計の約31%になる。**冷凍12袋の送料と、複数注文時の送料は未確認。原価データもDriveに見当たらず、粗利は算出できなかった。**

### 3.3 食品表示の不整合（Human確認必須）

1. **黒ごま海老餅の着色料**: 2023-06のラベル写真の原材料に「着色料」がある。ブランド情報シートにも「海老餅のエビに含まれる着色料が微量にある」とある。HPの `ingredients` は「もち米、干し海老、黒ごま、食塩」で、着色料がない。現行ラベルの原材料表示をHumanが確認し、HPとBASEをそれに合わせる必要がある。
2. **製造施設のアレルゲン注意書き**: ラベルには「小麦・大豆を使用した施設で製造」とあるが、HPには記載がない。
3. **賞味期限の日数**: ブランド情報シートは「製造から7日」、`data/` とFCP最新版は「8日」。正本は `data/`（8日）。ラベル実物と一致しているかを確認する。
4. **6枚入り**: `lib/shipping.ts` には「6枚入り（300g）はBASEで非公開」とある。しかし2026-10-09時点のBASEトップには6枚入り6商品（各660円）が並んでいる。

- FCPシートの記述「最もおいしい時期：11月新米期〜年末年始」は社外向けの資料。HPに使う場合はHumanの承認が必要。

### WP-2 BASEクリック計測の拡張（P0・WP-1から独立）

対象: `lib/analytics.ts`、`components/TrackedBaseLink.tsx`、`components/TrackedLink.tsx`。新規 `lib/base-click-items.ts`（純粋関数）、`components/TrackedBaseAnchor.tsx`・`components/TrackedLinkClient.tsx`（クライアント側のクリック処理）、`tests/base-click-items.test.mts`。**`SetLineup.tsx`・`app/` 配下・`tests/seo-safety.test.mts` は変更しない**（WP-1と衝突させない）。

設計上の制約（Claudeレビューで追加）: 逆引きはサーバーコンポーネント側で行い、`lib/analytics.ts` からカタログを値として import しない。計測のためにカタログ全体をクライアントJSへ送らないため。`TrackedBaseLink` と `TrackedLink` の利用箇所はすべてサーバーコンポーネントなので、両者をサーバーコンポーネントにし、クリック処理だけをクライアントコンポーネントに分ける（propsは変えない）。

1. `lib/base-click-items.ts`: BASEのURLから商品情報を逆引きする純粋関数 `baseItemForUrl(href)` を作る。
   - 固定セット8商品（`fixedSetVariants`）: `item_id`（variant id）、`item_name`（variant name）、`delivery`（`ambient` / `frozen`）、`bags`（6 / 12）、`purpose`（`home` / `gift`）。
   - 単品6商品（`products`）と選べる6袋（`catalogSets` の `choice-six-set`）: `item_id`（slug）、`item_name` だけ。配送方法・袋数・用途は送らない（推測しない）。
   - ショップトップなど一致しないURLは `undefined` を返す。
   - URLの一致は、末尾スラッシュとクエリを無視した完全一致にする。`six-flavor-gift` と `6-ambient-gift` は同じURLなので、固定セットを優先する。
2. `trackBaseClick(placement, item?)`: `base_click` に `placement` と、逆引き済みの商品パラメータを付けて送る。イベント名と `placement` の値は変えない。
3. `TrackedBaseLink`（サーバー）: `baseItemForUrl(href)` を計算して、クライアント側の `TrackedBaseAnchor` に渡す。これで `TrackedBaseLink` の全ての利用箇所が自動で対象になる。
4. `TrackedLink`: `external` で、かつBASEのURL（`https://yamadamochi.thebase.in/`）のときだけ、既存の `top_cta_click` などに加えて `base_click`（placement: `top_cta`）を1回送る。内部リンクでは送らない。
5. `StickyPurchaseBar`: 既存どおり `base_click`（`sticky_bar`）を送る。ショップトップなので商品パラメータは付かない。
6. 個人情報、検索語、URLのクエリは送らない。

受け入れ条件:

- BASEへの1クリックにつき、`base_click` は最大1回。
- 既存の `placement` の値、`top_cta_click` / `hero_cta_click` / `gift_cta_click` / `sales_channel_click` の送り方を変えない。
- 8つのセットがそれぞれ一意の `item_id` に対応する。

テスト:

- `baseItemForUrl`: 8セットの対応（一意性、delivery・bags・purposeの値）、単品6商品と選べる6袋の対応、ショップトップ・未知URL・末尾スラッシュ・クエリ付きURLの扱い。
- `trackBaseClick`: `window.gtag` をスタブして、1回の呼び出しで1イベントだけ送ること、payloadに想定外のキーがないこと。
- `TrackedLink` の判定関数（BASEの外部URLか）の単体テスト。
- クリック処理の関数を `window.gtag` のスタブで呼び、BASE外部リンク1クリックで `base_click` 1回＋既存イベント1回、内部リンクで `base_click` 0回になること。

### WP-3 年末年始のお届け案内（P1・仕組みだけ先に作る。日付はH-6の後）

対象: 新規 `data/winter-campaign.ts`、`lib/campaign.ts`、`components/WinterNotice.tsx`、`tests/winter-campaign.test.mts`。表示する場所は既存の `components/SetDeliveryGuide.tsx`（常温便・冷凍便の説明）の先頭だけにする。`SetDeliveryGuide` は `/products` と `/gift` の両方で、セット購入ボタンの直後に出る。`app/` 配下は変更しないので、WP-1・WP-5と衝突しない。

   - `displayFrom`、`displayUntil`（表示期間）
   - `ambientOrderDeadline`、`frozenOrderDeadline`（年内お届けの受付締切）
   - `lastShipDate`（年内の最終発送日）、`newYearShipStart`（年始の発送開始）

   - 置き場所はファーストビューの外なので、レイアウトのずれは小さい。
5. 文言: 「年内お届けの受付締切」と書き、到着日を保証する表現（「必ず年内に届く」など）は使わない。

## 12. GA4 で追加パラメータを使えるようにする手順（WP-2をmergeした後・Human）

1. GA4（`analytics.google.com`）で山田もち店のプロパティを開く。
2. 「管理」→「データの表示」→「カスタム定義」→「カスタムディメンションを作成」を開く。
3. 次の6つを、範囲「イベント」で1つずつ作る（ディメンション名は任意。イベントパラメータは下の文字列と一字一句同じにする）。

| ディメンション名（例） | イベントパラメータ | 値の例                                                      |
| ---------------------- | ------------------ | ----------------------------------------------------------- |
| BASEクリック位置       | `placement`        | `set_card`、`gift_hero`、`top_cta`                          |
| 商品ID                 | `item_id`          | `6-frozen-home`、`plain`                                    |
| 商品名                 | `item_name`        | 【冷凍便・ご自宅用】飛騨高山の切り餅 6種食べ比べ｜6袋セット |
| 配送                   | `delivery`         | `ambient`、`frozen`                                         |
| 袋数                   | `bags`             | `6`、`12`                                                   |
| 用途                   | `purpose`          | `home`、`gift`                                              |

4. 登録した日以降のデータから使える（過去のイベントにはさかのぼらない）。反映まで24〜48時間かかることがある。
5. 確認方法: 「レポート」→「エンゲージメント」→「イベント」→ `base_click` を開き、作成したディメンションで内訳を見る。リアルタイムで確かめたい場合は「管理」→「DebugView」を使う。
